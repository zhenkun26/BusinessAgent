## Why

项目已于 v1.2.0 归档完结，工程基线（文档、测试、安全修复、部署清单）齐备，但按「真实企业上线」标准（见根目录评审 IMG_5043/5044 与 `docs/40-process/优化方向分析-生产上线-2026-08-05.md`），上线决策所依赖的顶层契约——系统边界、SLA、风险操作清单——仍散落在产品文档与 README 中，没有正式规格，导致后续压测达标、UAT 验收、灰度放行都缺少可引用的度量基线。评审将此列为第一阶段（需求冻结、数据/权限梳理、架构评审），是其余优化方向的前置。

## What Changes

- 新增正式规格，冻结三类上线契约：
  - **系统边界**：系统负责什么、不负责什么（对接系统清单、数据所有权、人工兜底边界）。
  - **SLA 指标体系**：可用性、延迟（p95/p99）、错误率、恢复时间（RTO/RPO）的目标值与度量口径，作为后续压测与验收的达标线。
  - **风险操作清单**：需审批/审计的高危操作全集（外部发送、批量变更、删除、权限调整等），与现有审批/审计能力对齐。
- 架构评审结论落入 `docs/40-process/DECISIONS.md`（单一事实源），数据/权限梳理结论落入产品文档。
- 本 change 只产出规格与决策记录，不改业务代码。

## Capabilities

### New Capabilities
- `production-readiness`: 系统边界声明、SLA 指标体系（可用性/延迟/错误率/RTO/RPO 的目标值与度量口径）、风险操作清单及其审批与审计要求，作为压测、UAT、灰度放行的统一达标基线。
