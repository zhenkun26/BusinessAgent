# 发布灰度与上线门槛检查单

> 状态：草案（2026-08-15）
>
> 本文定义灰度和放行方法，不代表项目已经全量上线。任何未具备证据的项目必须保持未勾选，并在 `docs/40-process/ISSUES.md` 中保留缺口。

## 1. 灰度策略

当前部署形态是单机 Docker Compose，暂不引入流量染色或蓝绿部署。灰度按用户范围逐级放量：

| 阶段 | 范围 | 最短观察期 | 放量前提 |
|---|---|---:|---|
| G0 | 种子用户技术彩排 | 1 个工作日 | 环境、数据、日志、回滚均可用；不算正式灰度 |
| G1 | 销售部真实员工 | 1-2 周 | UAT 核心场景通过，产品负责人批准 |
| G2 | 销售部 + 客服部 + 财务部 | 1-2 周 | G1 指标持续达标，无 P0/P1 |
| G3 | 全部目标用户 | 2 周以上 | G2 结论签署，放行检查单全部满足 |

总观察期不少于 2-4 周。每一级都必须保留放量时间、用户范围、版本号、指标快照、问题单和继续/回滚结论。

## 2. 观察指标

### 2.1 硬门槛

以下指标引用 `openspec/specs/production-readiness/spec.md`，不得临时修改口径：

| 指标 | 达标线 | 数据来源 |
|---|---:|---|
| 可用性 | ≥99.5% | Prometheus/访问日志 |
| 核心接口 p95 | ≤2s | Prometheus/k6 |
| 核心接口 p99 | ≤5s | Prometheus/k6 |
| 错误率 | <0.5% | Prometheus/审计日志 |
| RTO | ≤1h | 备份恢复演练记录 |
| RPO | ≤24h | 备份策略与恢复记录 |

### 2.2 业务观察项

以下指标用于灰度判断，但正式阈值需要产品负责人在 UAT 评审时确认：

- 核心任务完成率；
- 用户人工接管率；
- 审批平均耗时和超时率；
- 工具调用成功率与 Saga 补偿失败率；
- RAG 点踩率、拒答率和来源命中情况；
- 外部系统错误、重复写入和审计缺失数量。

## 3. 回滚触发条件

满足任一条件，立即停止继续放量并进入回滚评估：

- 出现 P0/P1 缺陷；
- 错误率、p95 或 p99 突破硬门槛；
- 出现权限越界、敏感数据泄漏或未经审批执行；
- 外部系统重复写入、错误发送或补偿失败无法人工接管；
- 备份不可用或恢复路径失效；
- 业务负责人判断核心任务结果不可信。

## 4. 回滚路径

1. 停止新增用户和新增放量；
2. 记录当前版本、问题、影响范围和最后一个可用时间点；
3. 对业务连接器先关闭对应 provider 或入口，避免继续产生外部副作用；
4. 回退到上一稳定镜像 tag，或按运维手册恢复上一稳定版本；
5. 必要时使用最近一次可验证备份恢复，禁止直接清库或覆盖生产数据；
6. 验证 `/health`、`/ready`、认证、权限、审批和审计链路；
7. 修复后重新从 G1 开始灰度，不得直接跳回原放量阶段。
