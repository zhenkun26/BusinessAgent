## 2. 本机环境特殊性(踩过的坑,别再踩)

| 事项 | 说明 |
|------|------|
| Python 解释器 | conda 不在 PATH,用绝对路径 `/d/ProgramData/anaconda3/envs/enterprise_agent/python.exe`(env 名 `enterprise_agent`,Python 3.11.15) |
| 终端 | 一切命令在 **Git Bash** 执行;PowerShell 不支持 `<` 重定向/`VAR=值` 前缀/heredoc |
| 中文乱码 | 命令前加 `PYTHONIOENCODING=utf-8`;curl 中文 body 必须 `--data-binary @文件`,不能 `-d` 直接写 |
| 端口残留 | 重启 API 前先查:`netstat -ano \| grep :8000` \| 有残留则 `taskkill //PID <pid> //F` |
| uvicorn reload | Windows 上不可靠(卡死),所以启动命令不带 --reload;改代码后手动重启 |
| Docker 依赖 | API 起不来先查 `docker ps`——Docker 没启是最常见原因(PG 连接拒绝) |
| 模型路径 | bge-m3 / bge-reranker-large 在 `D:/models/`;首次调用有冷加载(首请求 +30-60s) |

## 3. 常见维护操作

### 3.1 知识库:入库新文档

```bash
PY=/d/ProgramData/anaconda3/envs/enterprise_agent/python.exe

# 公司共享文档(所有人可见)
$PY -m app.rag.ingest <文件或目录> --type policy --ns shared_company

# 部门专属文档(必须显式指定角色,否则默认全角色可见!)
$PY -m app.rag.ingest <文件> --type policy --ns dept_sales --roles salesperson manager admin
```

- 分区可选:`dept_sales / dept_finance / dept_cs / dept_hr / shared_company / restricted_exec`
- `--type`:`policy / product / faq / manual`
- **入库是增量追加,日常加文档直接跑 CLI 即可,不要 recreate Collection**——全量重建(init_milvus(recreate=True) + run_w9_milvus)仅用于开发期推倒重来,且会清掉 dept 分区文档需逐个补入
- 传错分区名会静默落入 shared_company(有 warning 日志),注意看输出
- 验证:`docker compose exec -T postgres psql -U agent enterprise_agent -c "SELECT count(*) FROM …"` 或前端直接提问测

### 3.2 用户管理(成员加入/变更/离职)

> 原则:**日常变更一律增量 SQL,不要清库重建**——DROP SCHEMA 会把 sessions/audit_logs/approval_requests 一起抹掉,仅用于开发期整体重置。init.sql 底部的种子区只对**新库**生效;改现库直接 SQL,两者互补(新成员最好两边都加)。

**新成员加入**(无需动 init.sql、无需重启):

```bash
docker compose exec -T postgres psql -U agent enterprise_agent -c "
INSERT INTO users (user_id, username, email, role, department)
VALUES ('user_sales_004', '新同事赵六', 'zhaoliu@company.com', 'salesperson', 'dept_sales')
ON CONFLICT (user_id) DO NOTHING;"
```

- `role` 必须是 5 角色之一:salesperson / customer_service / finance / manager / admin
- `department` 必须是分区命名空间:dept_sales / dept_finance / dept_cs / dept_hr / shared_company
- 这两个字段直接决定可用工具(RBAC)和可见文档(命名空间),填错=权限错
- 登录用 `username`(开发期不校验密码)

**改角色/部门/离职**:

```bash
PSQL="docker compose exec -T postgres psql -U agent enterprise_agent"

# 升职改角色
$PSQL -c "UPDATE users SET role='manager' WHERE username='销售员张三';"
# 调部门(角色通常要一起改)
$PSQL -c "UPDATE users SET department='dept_finance', role='finance' WHERE username='销售员张三';"
# 离职(软删除,保留审计追溯)
$PSQL -c "UPDATE users SET is_active=false WHERE username='销售员张三';"
```

**生效时机**:JWT 里携带 role/department,已签发的 token 在过期前仍是旧权限——改完让本人重新登录(或等 token 过期)才生效。JWT 过期时间见 `.env` 的 `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`。

**PowerShell 导入 SQL 文件时**:先 `$OutputEncoding = [System.Text.Encoding]::UTF8` 再 `Get-Content -Encoding UTF8 | docker exec -i … psql`(否则中文种子变 `?????`;判断数据是否真坏用 `SELECT username, octet_length(username) FROM users`,中文应 = 字数×3)。

**已知缺口**:系统无用户管理 API,成员变更全靠手敲 SQL;上线前值得加 admin 专用用户管理端点(backlog)。

### 3.3 Prompt 管理

- 界面:`/ui` → Prompt 管理(admin/manager)
- 回滚 = 激活旧版本;A/B = 双 active + 流量权重
- **注意 `str.format` 转义**:模板里 JSON 示例的花括号必须写 `{{ }}`,否则运行时 KeyError
- DB 不可用时系统自动降级到代码内置默认(`app/prompts/defaults.py`),日志有告警

### 3.4 数据库速查

```bash
PSQL="docker compose exec -T postgres psql -U agent enterprise_agent"

# 会话状态分布
$PSQL -c "SELECT status, count(*) FROM sessions GROUP BY status;"
# 审计事件分布
$PSQL -c "SELECT event_type, count(*) FROM audit_logs GROUP BY event_type ORDER BY 2 DESC;"
# 审批单
$PSQL -c "SELECT approval_id, status, risk_level, created_at FROM approval_requests ORDER BY created_at DESC LIMIT 10;"
# Prompt 版本
$PSQL -c "SELECT name, version, status, traffic_weight FROM prompt_versions ORDER BY name, version;"
# 反馈与知识候选
$PSQL -c "SELECT feedback_type, count(*) FROM user_feedback GROUP BY 1;"
$PSQL -c "SELECT title, status FROM documents WHERE status='draft';"
```

### 3.5 备份

```bash
# PG 逻辑备份
docker compose exec -T postgres pg_dump -U agent enterprise_agent | gzip > backups/pg_$(date +%Y%m%d).sql.gz
# 恢复
gunzip < backups/pg_xxxxxx.sql.gz | docker compose exec -T postgres psql -U agent enterprise_agent

# Milvus 数据卷(docker volume,整卷备份)
docker run --rm -v enterprise-agent_milvus_data:/data -v $(pwd)/backups:/b alpine tar czf /b/milvus_$(date +%Y%m%d).tar.gz -C /data .
```

Redis checkpoint 属会话状态,不纳入常规备份(丢了=历史会话不可续,业务数据不受影响)。

## 5. 故障排查

| 现象 | 处理 |
|------|------|
| API 起不来,报 ConnectionRefused | `docker ps` 查基础设施;没启先 `docker compose up -d …` |
| API 起不来,端口被占 | `netstat -ano \| grep :8000`,`taskkill //PID <pid> //F` |
| 前端 /ui 空白 | F12 看 Console;CDN(vue/marked)需要联网;Ctrl+F5 强刷 |
| 前端 sources 显示 0.000/空标题 | 该 bug 已于 2026-07-26 修复(LangChain 序列化 kwargs 未解包,详见第 8 节);确认 API 已重启加载新代码 |
| 审批批准后状态卡在 approved_pending_reauth | 种子审批单缺 requester_token(2026-07-27 已修,见第 8 节);跑 `scripts/fix_seed_approvals.py` 补 token;动态建单出现此状态则是发起人 token 真过期,需其重新登录后 resume |
| 审批显示 executed 但工具执行失败 | 2026-07-27 起审批结果直接显示失败原因(message 字段);常见原因:发起人角色与工具不匹配(RBAC,如 salesperson 用 create_ticket) |
| 前端改了不生效 | index.html 是静态文件无需重启 API,但浏览器有缓存,Ctrl+F5 强刷 |
| 知识问答"未覆盖"但文档在 | 置信度兜底(拒答优于编造);用 `eval/run_p2_namespace.py` 验证检索;已知一例召回排序问题(P3 待办) |
| Milvus 检索返回 0 条 | 查 collection 实体数:`/ready` 的 `milvus.num_entities`;0 则需重新入库(手册 0.2) |
| checkpointer 显示"未初始化" | 正常,首次对话后惰性初始化;应为 redis,降级则查 RediSearch 模块 |
| 首次请求特别慢(100s+) | 模型冷加载,第二次起正常 |
| audit_logs 无新记录 | PG 是否 healthy;审计降级时会写 `logs/audit/` 本地文件 |

## 6. 升级与改动注意事项

- **改代码后**:重启 API(无热更);涉及 graph/agents 的改动跑 `eval/run_w5_e2e` + `eval/run_w7_execution` 回归

### 2026-07-28 回答质量修复:意图分类路由 + 运行时 flash 回退 / 闲聊人格化 / 加粗渲染

- **现象**:①「查询订单 ORD-2026-001 的详情」被路由到知识问答,回答"知识库未覆盖";② 闲聊话术机械重复("我是企业知识助手…"),与小A 品牌不符;③ 折扣政策回答中 `**5%-10%**` 显示字面星号

- **修复**:
  1. `planner_intent_classify` 模板:补齐 data_operation(查询或变更具体业务记录)/knowledge_qa(仅政策制度)定义与判定规则;`RULE_KEYWORDS` 同步加"查询订单/ord-/工单/查客户"(已 UPDATE prompt_versions v1——启动同步 ON CONFLICT 不覆盖,必须手动改)

  4. 前端 `renderMd` 预处理:`**x**` 统一转 `<strong>` 再交 marked,绕开侧翼规则
  5. `knowledge_rag_answer` 模板加引导:问具体业务记录时提示改用查询指令(兜底路由仍漏的场景)
