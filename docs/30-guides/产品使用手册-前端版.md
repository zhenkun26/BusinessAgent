## 1. 主线:多人协作审批闭环(核心演示,约 5 分钟)

> 故事:销售员要给客户发外部报价邮件 → 高风险操作必须先经经理审批 → 经理批准后自动执行 → 销售员随时能跟踪进度。两个账号接力,全程在 /ui 完成。

**第一棒 · 销售员张三(发起)**

1. 登录 **销售员张三**。打开「✨ 场景」弹窗,点「销售场景」分组里的外部邮件项(或输入:`给客户 C001 的联系人张经理发一封外部邮件,邮箱 zhang@huaxin-tech.com,主题:续约报价,正文:本季度续约报价请查收`)。
2. 预期回答:「以下操作已提交审批(审批号 appr_xxx),待经理审批后自动执行: send_email_external」。**邮件此时没有发出**。(若话术里不给收件人邮箱,智多星 会先查出联系人邮箱并请你确认,不会直接建单——见「已知边界」。)

**第二棒 · 销售经理赵六(审批)**

3. 退出,登录 **销售经理赵六** →「审批」页签 →「待我审批」看到该单(high 橙色标,操作类型 send_email_external)。
4. 点「批准」(可填意见)。预期:toast「已批准:审批已通过, 工具已执行: …message_id EXT-xxx」,卡片 1 秒后从列表消失。

**第三棒 · 回到张三(跟踪)**

5. 退出,登录回 **销售员张三** →「审批」页签 →「我的审批」:该单状态「已执行」绿色徽标,显示审批人 user_mgr_001、决策时间和审批意见。
6. 对话里直接问:`我的审批到哪了` → 命中 query_my_approvals 工具,返回真实审批状态列表(不再穿帮)。

**闭环讲解要点**

- RBAC:销售员有外部邮件权限,但工具 `requires_approval=True`,发起即挂起——权限决定"能不能发起",审批决定"能不能生效"
- 批准后服务端以发起人身份**同步执行** prefill_payload,不需要发起人再发消息
- 若发起人 token 已过期:状态落「已批准·待恢复」(approved_pending_reauth),「我的审批」里出现「恢复执行」按钮,重新登录后一键补执行
- 每一步都有审计落库(approval_created / approval_decision)
- 审批页三区块视角:**待我审批**=等我决策的队列(批完即消失);**我经手的**=我批过/拒过的历史留痕(按 approver_id,仅经理/管理员可见);**我的审批**=我发起的单的进度跟踪(按 requester_id)。张三发起的单被赵六批准后,出现在张三的「我的审批」和赵六的「我经手的」两处

## 2. 张三(销售员):对话核心能力

1. **系统状态** → 数据库/Milvus 绿色 healthy,工具 8(Checkpointer 首轮对话后变 redis)。
2. **业务数据** → 4 张子表:客户 8 行 / 订单 8 行 / 工单 6 行 / 文档 7 行。点 C001 行「查询」→ 自动跳回对话页并填入查询语句。
3. **闲聊**:「✨ 场景」→「通用」分组点「你好」→ 智多星 人格话术(含身份称呼,如「你好，销售员张三！我是智多星～…」),意图 chitchat,置信度 0.90,无来源。v3.3 起闲聊扩展为九类分支——问候/自我介绍(你是谁)/心情状态(你今天心情怎么样)/能力询问(你会什么)/日常寒暄(吃了吗/周末/加班)/情绪共情(我今天心情不太好)/感谢/再见 + **未命中话题由本地 qwen 按智多星 人格即兴生成**(如「今天天气真不错」,回复自然带称呼、全角标点);LLM 异常时回默认模板。
4. **知识问答 + 多轮上下文**:`销售提成政策是怎么规定的?` → 答案带 [来源N];**同会话**追问 `那它的折扣呢?` → 承接上文围绕折扣政策。
5. **命名空间命中**:`冲刺先锋奖的评选规则是什么` → 命中《销售部内部激励方案》(dept_sales)。
6. **工具-查客户**:`查一下客户 C001 的信息` → 北京华信科技 VIP 客户数据。
7. **工具-查订单**:`查询订单 ORD-2026-005 的详情,包含明细` → ¥45,000 待付款 + SKU 明细。
8. **多动作单任务(双写已修复)**:`给客户 C001 创建一个回访任务,并发内部邮件通知经理赵六` → **只创建一个任务**(CT-xxx)+ 一封内部邮件(INT-xxx),同一执行分支顺序完成;不再出现两个重复任务。
9. **取消**:发送 `公司的折扣审批政策是怎样的`,进度条出现时**立刻点「取消」** → 回答区显示 cancelled;同会话再发 `你好` → 正常。
10. **反馈**:任意回答点 👍;另一条点 👎 填原因 → 「已记录,负反馈将生成知识候选草稿」。

## 已知边界(不是 bug,别再排查)

| 现象 | 说明 |
|------|------|
| 行业分布类分析回答「缺少行业维度」 | 聚合计算目前不带 industry 字段,能力边界,回答会如实说明 |
| 销售员/客服更新工单类话术得到「未识别到需要执行的工具操作」 | RBAC 前置在 planner 之后,该话术未被识别为工具调用;验证 RBAC 拒绝请用第 15 步的外部邮件场景 |
| 「创建任务并由经理审批」直接执行了 | create_crm_task 是低风险直执;演示审批请用外部邮件(第 1 章) |
| 发外部邮件但没给收件人邮箱时,只回了客户信息没建审批单 | 2026-07-27 起的设计行为:缺必要参数(如收件人邮箱)不建审批单,智多星 会先查联系人并请你确认;确认后再发一次即正常建单。避免审批负载冻结空参数、批准后执行失败 |
| 对话问审批进度的回答偏"工具回执"风格 | 已于 2026-07-27 修复:工具结果统一模板化格式化为中文话术(execution._fmt_tool_output) |
