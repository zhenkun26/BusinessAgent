# Hello，小A——企业知识工作流 Agent — 全流程使用案例手册

> 用途:手工逐项验证系统全部功能(P3 前的功能基线)
> 环境:Windows + **Git Bash** + conda 环境 `enterprise_agent`
> 日期:2026-07-27(与 P2 完成后的代码实测状态一致;前端 v2 业务场景化增强)
>
> **⚠️ 全部命令必须在 Git Bash 中执行,不能在 PowerShell!**
> (开始菜单搜 "Git Bash",或在文件夹右键 → Git Bash Here;再或 VS Code 终端切换为 Git Bash)
> PowerShell 不支持 `<` 重定向、`PY=...` 赋值、heredoc,直接粘贴会报 ParserError。
>
> **执行前必读(Windows 两个坑)**:
> 1. curl 直接 `-d` 中文会编码损坏 → 本手册一律用 `cat > /tmp/xxx.json <<'EOF'` 写文件 + `curl --data-binary @文件`
> 2. uvicorn reload 在 Windows 偶发卡死 → 启动 API 用不带 reload 的方式(见 0.3)

### 0.5 浏览器前端(/ui,推荐的手工测试方式)

API 启动后直接打开:

```
http://localhost:8000/ui
```

单文件 SPA(无需 Node/构建),覆盖手册大部分测试:

- **登录**:10 个种子用户下拉直选(覆盖 5 角色 × 4 部门);登录页显示角色/部门标签;token 存浏览器 localStorage
- **对话**页签:
  - markdown 渲染、来源/置信度/延迟徽标、**流式输出**(节点进度 + 打字机 token;SSE `/chat/stream`)
  - 长请求**取消按钮**、👍/👎 反馈、新会话/历史
  - **业务场景快捷面板**(按角色显示不同 chips):销售/客服/财务/管理 各有专属场景,点击直接填入对话
- **业务数据**页签(全部角色可见):客户/订单/工单/知识库文档 4 张参考表,与 init.sql 及 CRM/工单 Mock 同源;每行带「查询」按钮一键发问
- **审批**页签(经理/管理员):待审列表、批准/拒绝、批量审批 batch_id 标识
- **Prompt 管理**页签(经理/管理员):版本列表、建 draft、激活(回滚)、A/B 流量
- **系统状态**页签:/ready 依赖健康一览

角色感知:销售员/客服/财务只见「对话 + 业务数据 + 系统状态」;经理/管理员额外多「审批 + Prompt 管理」。以下章节仍以 curl 为准(便于脚本化),喜欢点界面的话,直接看 **第二部分:网页前端版全流程(F1-F14)**,与 curl 版一一对应。

## 16. 故障排查速查

| 现象 | 原因与处理 |
|------|-----------|
| PowerShell 报 `“<”运算符是为将来使用而保留`、`无法将"PY=..."项识别为 cmdlet` | **你在 PowerShell 里跑了 Git Bash 命令**;换 Git Bash(见手册开头警告),仅 0.2 节提供 PowerShell 版 |
| curl 返回 `There was an error parsing the body` | 中文编码坏了;必须 `--data-binary @文件`(本手册 0.4 的方式) |
| 首次知识问答特别慢(100s+) | bge-m3/reranker 冷加载,第二次起正常 |
| 中文输出乱码 | 终端编码问题,命令前加 `PYTHONIOENCODING=utf-8`;数据本身无碍 |
| `/ready` 里 checkpointer 显示"未初始化" | 正常,首次对话时才惰性初始化;对话后应为 redis |
| 答案「现有知识库未覆盖」但文档明明在 | 置信度兜底(拒答优于编造);召回排序问题已于 2026-07-26 修复(政策场景共享优先平局裁决),可用 `eval/verify_recall_fix.py` 确认 |
| API 改代码后不生效 | uvicorn reload 在 Windows 不可靠,手动重启(0.3 的方式本来就没开 reload) |
| 查询 sessions 显示旧状态 | 终态反映最新一轮;历史状态变迁看 audit_logs |
