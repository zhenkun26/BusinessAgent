> 基线日期：2026-10-17；应用版本：1.3.0；代码调查基线：`153f78651217eec7544b064446344d27b36085f1`。
> 状态：S0/C24 前置已推送；C01 配置修复已完成但目标运行验收 BLOCKED，25 项整项仍未按本基线验收。当前进度见 ROADMAP，推进下一项仍需用户确认。

## 1. 交付目标与适用范围

目标是让维护者依照文档，在隔离环境部署并实际执行知识问答、数据分析、受审批控制的业务操作，能够验证权限、恢复行为与运行状态。项目目前没有真实企业使用；历史「企业级」「内部验证」「生产化」描述不构成企业现场生产证据。

本轮确定的支持边界如下。表中「待实测」是后续 C 项的交付任务，不是当前已支持承诺。

| 维度 | 工程交付范围 | 完成条件 / 限制 |
| --- | --- | --- |
| 组织与角色 | 单组织，现有角色体系与部门隔离 | C04/C05/C07/C20 固定角色 × 部门 × 操作矩阵；manager 跨部门策略必须明确，未授权即拒绝 |
| 部署 | Linux 单机 Docker Compose，入口代理、API、独立 worker | C01 绑定同一候选镜像摘要；不依赖源码挂载；macOS/Windows 为开发入口，K8s 为未验收参考 |
| 基础设施 | 真实 PostgreSQL、Redis、Milvus 及其配套存储 | C03/C10/C15/C22 验证迁移、持久化、一致性与恢复；不能用内存降级冒充持久化成功 |
| 模型 | 一套明确的 LLM / embedding / reranker profile | C02 基于现有适配器选择并记录具体供应方、版本/模型标识、依赖、资源与网络条件，实际加载和调用通过；不承诺所有组合 |
| 进程 | 首选支持声明与部署配置一致 | C09 在至少两个 API 进程验证跨进程状态；若收窄为单 API 进程，必须同步配置、文档并经该项确认，不声称 HA |
| 外部系统 | 受控 CRM、工单、邮件 HTTP 参考服务与受控 IdP | C18/C19 经完整应用链路；参考服务包含持久化、鉴权、幂等及故障行为；邮件进入测试收件器，不发真实收件人 |
| 数据 | 明确标识的合成业务数据、样例知识与测试身份 | 数据可替换；无真实客户数据与企业凭证；C16 不能继续暗用内置 Mock 分析数据 |
| 用户入口 | 浏览器 UI 与已公布 API | C20 按角色逐流程人工验收；未提供 UI 的功能明确使用 API，不要求本轮重做前端 |
| 运维 | 就绪、审计、指标、受控告警接收、备份恢复与回退 | C21/C22 记录实测结果；不自动删除文件或数据卷，不用长期可用率目标代替测量 |

本轮不承诺：真实企业 UAT、真实提供方商业契约、企业灰度/生产部署、长期 SLA、多租户、多主机 HA、完整 DAG、长期用户记忆。已有公开接口涉及这些能力时，必须修复或显式限制，不能静默忽略。

## 2. 文档与 OpenSpec 的责任划分

- [ISSUES：C01–C25](../40-process/ISSUES.md#engineering-closeout)：逐项现状、代码证据、缺口、优先级、验收与当前状态的唯一事实源。
- [ROADMAP：S0–S7](../40-process/ROADMAP.md#engineering-closeout-stages)：执行顺序、依赖与暂停点的唯一事实源。
- [DECISIONS：决策 20](../40-process/DECISIONS.md#engineering-delivery-decision)：边界决策及改判条件。
- [engineering-delivery-closeout](../../openspec/changes/engineering-delivery-closeout/proposal.md)：本轮治理契约与实施任务。S0 后保持 active，不能提前归档或同步未实现的运行时能力。
- [crm-mail-sso-integration](../../openspec/changes/crm-mail-sso-integration/tasks.md)：真实企业系统的契约与联调继续独立阻塞。
- [uat-and-ga-rollout](../../openspec/changes/uat-and-ga-rollout/tasks.md)：真实用户、安全验收、最短四周灰度与放行签署继续独立管理。

P0 表示先处理权限、数据或副作用风险；P1 表示完成工程交付仍必须满足的条件。C01–C25 全部在范围内。实施中如需延期、替换或收窄某项，先说明对整体交付的影响并取得用户确认，不自行把 FAIL/BLOCKED 改成 NOT_APPLICABLE。

## 3. 参考集成契约

| 系统 | 必须冻结的契约 | 必须覆盖的故障与边界 |
| --- | --- | --- |
| CRM | 查询/分析数据与建单字段、鉴权、唯一操作 ID、幂等键持久性、补偿语义 | 重复与不同动作、响应丢失、超时/401/5xx、字段缺失、部分成功 |
| 工单 | 创建/更新、原值记录、幂等重放、补偿关闭或恢复 | 同键不重复创建、不同动作不串单、失败重试与补偿失败可见 |
| 邮件 | 内/外发送、测试收件器、服务端回执 ID、幂等或查询去重 | 已发但响应丢失不能盲重试；撤回不支持/仅发撤回请求不得显示撤回成功 |
| IdP | authorize/token/JWKS、issuer/audience、state/nonce、claims、账户映射 | 真实签名、浏览器回调、错误签名/过期/重放、密钥轮换、禁用用户、身份映射冲突 |

参考服务必须明确标为项目自控实现。只有进程内 MockTransport 或返回固定成功的 stub，不足以作为完整工程集成证据。真实提供方到位后仍需逐条验证契约差异。

## 4. 验收证据与状态

| 证据层 | 含义 | 不能替代 |
| --- | --- | --- |
| E0 静态 | 代码/配置/文档调查与结构校验 | 实际运行、缺陷复现或修复通过 |
| E1 自动化 | 单元、契约、故障注入测试；标记 Mock 边界 | 完整基础设施和浏览器操作 |
| E2 完整参考环境 | 候选镜像 + 真实基础设施 + 受控外部服务，走应用入口 | 企业提供方联调和业务认可 |
| E3 人工交互 | 在记录的浏览器与角色下逐步骤操作 | 企业用户 UAT 或长期运行 |
| E4 企业现场 | 真实提供方、用户、安全、灰度和签署 | 本轮无资源，保持 BLOCKED |

PASS = 对应标准已执行且结果满足；FAIL = 已执行且不满足；BLOCKED = 前置资源/工具/授权缺失未能执行；NOT_APPLICABLE = 经说明确认与该项无关。计划任务另记 open / in_progress / done；不能把任务 open 写成测试 FAIL。

每项验收记录至少包含：

1. C 编号、验收条款、授权范围、代码提交、镜像摘要、执行时间。
2. 系统/硬件、容器与依赖版本、模型标识、数据集哈希、角色和配置摘要（不含密钥）。
3. 命令或人工步骤、预期结果、实际结果、证据路径与 E0–E4 等级。
4. PASS/FAIL/BLOCKED/NOT_APPLICABLE、失败原因、未覆盖范围、复验条件。
5. 数据副作用与保留资产位置；禁止自动删除，需清理时交由用户操作。

每项交付前补受影响回归；任何后续代码或配置改动会使受影响证据失效。S7 必须绑定最终候选重新验证，不以旧版 CI 或历史压测直接放行。

## 5. 性能、恢复与质量口径

- C17 保留 122 条既有评测及其来源，答案关键词覆盖目标 ≥0.85；同时公开全部样本分母、失败/跳过数、错误归因和来源正确性。关键词覆盖不等于事实正确率；权限泄漏、越权引用与无依据编造不能被均值掩盖。
- C23 在执行前冻结硬件、模型、数据量、并发、业务混合比例、限流和样本量；至少 30 分钟稳定混合运行，覆盖问答、分析与受审批的参考业务链路，不能用 health 流量总量声称业务容量。
- 保留既有 p95 ≤2s、p99 ≤5s、错误率 <0.5% 作为历史基准，按接口/请求类型分别报告；LLM TTFT、完整响应、排队/执行耗时分别统计，禁止用 TTFT 替代完整响应。C23 执行前对适用负载与阈值做显式确认；若无法满足，记录 FAIL 或先评审范围变更，禁止事后调线制造通过。
- C22 恢复目标沿用 RTO ≤1h、RPO ≤24h；使用当前版本、隔离副本与有时间戳的数据实测，记录 PG、Milvus 对象/元数据及必要运行状态的一致恢复。未落实备份周期时不能宣称日常 RPO 达标。
- 30 分钟测试不证明月度可用率；历史可用性目标不能表述为已测得 SLA。

## 6. 工程完成条件与停止点

工程交付完成要求：C01–C25 按批准范围全部验收、无未解决的范围内 P0/P1、E1/E2 通过、适用 E3 完成、部署/恢复文档可按步骤复现、最终提交与证据一致、OpenSpec 严格校验及归档条件满足。资源缺失导致的工程必需项 BLOCKED 会阻止工程完成；企业现场 E4 单独阻塞不伪装为工程失败或已上线。

允许的最终结论是：「工程交付验收通过，企业现场生产验证未开展」。当前 S0 尚不能使用该完成结论。`formal_uat=false`、`release_evidence=false`、`release_allowed=false` 保持；不修改现有门槛文件来制造通过。

S0 已按用户确认进入 C24 前置；之后每个 C 项按范围、实现、证据、限制交付并暂停。推送当前提交需另有明确授权；合并、发布、部署也需单独授权。没有企业资源不阻止可离线部分形成可复核工程证据，但不能跳过真实上线要求。

C24 前置提供[离线安全入口](safe-validation.md)与[证据模板](../40-process/模板-工程验收证据.md)；它只核验既有计划/G0，不包含应用、容器、模型与浏览器验收。
