## 二、数据资产与权限梳理（任务 1.2）

**数据资产**：

- PostgreSQL 9 表：`users` / `sessions` / `approval_requests` / `audit_logs` / `user_memories` / `saga_transactions` / `user_feedback` / `documents` / `prompt_versions`（deploy/init.sql）
- Milvus：单 collection（`settings.milvus_collection`），文档分块向量，按 `dept_namespace` 过滤
- Redis：任务队列、checkpoint、缓存
- 所有权：业务数据（CRM/工单/邮件）归各外部系统，本系统只读写不拥有；知识文档归本系统（documents 台账 + 向量副本）

**权限模型**（`app/security/rbac.py`）：

- 5 角色：salesperson / customer_service / finance / manager / admin
- 工具白名单 `ROLE_TOOLS`：逐角色授权 8 个工具子集
- 命名空间 `ROLE_NAMESPACES`：admin=`*`；manager 跨四部门 + shared_company；其余角色仅本部门 + shared_company
- 审批终审原则：经理批准后仍按发起人角色过 RBAC（DECISIONS #7），审批不是提权通道

## 三、部署与运维事实（任务 1.3）

- 单机 Docker Compose（docker-compose.prod.yml）：api(4 workers) + worker + Nginx(TLS) + Milvus/etcd/MinIO + PG + Redis + Prometheus/Grafana(profile)
- 备份：每日 pg_dump + etcd snapshot（DEPLOY.md 文档脚本），**无恢复演练记录**
- 监控：Prometheus 指标已暴露，**无告警规则与值班预案**
- 高可用：无多副本故障转移；K8s 8 清单已备未启用
- 性能参照：RAG 评测平均延迟 1049ms（22 条）；一次 1000 并发冒烟 0 失败（非正式压测）

## 四、系统边界声明（草案，任务 2.1）

**系统负责**：自然语言知识问答（RAG）、数据分析（Python 聚合）、业务执行编排（工具 + Saga + 审批）、知识库运营（录入/审核/激活）、用户与权限管理。

**系统不负责**：

- CRM/工单/邮件系统的业务数据正确性与可用性（外部系统自治，本系统只做调用方）
- 审批内容本身的业务合理性判断（审批人职责）
- 企业 IdP/SSO 的账号生命周期（SSO 接入后仍由 IdP 拥有）

**人工兜底边界**：低置信度拒答转人工；Saga 补偿失败记录 `compensation_errors` 转运维介入（DECISIONS #6）；审批超时自动流转并通知，不自动通过。

## 五、SLA 指标体系初值（草案，任务 2.2）

| 指标 | 初值 | 度量口径 | 数据来源 |
|---|---|---|---|
| 服务可用性 | ≥ 99.5%（单机现实上限） | 月度，/health 可服务时间占比；依赖降级（如 Milvus 故障走 PG 降级）计为可用但标注降级状态 | Prometheus |
| 核心接口延迟 | p95 ≤ 2s，p99 ≤ 5s | 对话类接口以首 token 计；管理类接口以完整响应计 | Nginx 日志 / Prometheus |
| 错误率 | < 0.5% | 5xx 占总请求比（月度） | Nginx 日志 |
| RTO | ≤ 1 小时 | 故障发生到服务恢复 | 演练实测 |
| RPO | ≤ 24 小时 | 对齐每日备份频率 | 演练实测 |

初值按单机 Compose 现实设定（见 design.md 决策 2），`load-test-and-dr-drill` 压测与演练后必须回访校准。

## 六、风险操作清单（草案，任务 2.3）

判定标准：触达外部系统的写操作、影响多用户的权限/内容变更、不可逆或难补偿操作。批量界定：**任何单次调用影响 >1 条记录的变更即视为批量**（当前无批量入口，未来出现即列入）。

| 操作 | 风险 | 现有约束 |
|---|---|---|
| send_email_external 对外发邮件 | 对外声誉、不可撤回（只能发撤回信） | `requires_approval=True` + 审批后按发起人角色终审 |
| create_crm_task / create_ticket / update_ticket | 外部系统脏数据 | Saga 补偿 + 审计 |
| POST /prompts/{name}/activate、PUT traffic | 全量用户回答质量 | admin 限定 |
| POST/PATCH /admin/users（建号/禁用/角色调整） | 权限安全 | admin 限定 + 审计 |
| knowledge-candidates approve/reject | 知识库内容质量 | admin 限定 |
| approval decide / batch-decide | 审批权力本身 | 角色限定 + 审计；batch-decide 属批量操作 |
| ingest --recreate（删除重建 collection） | 知识库全量清空 | 脚本自带危险警示，仅运维手动 |

清单内操作均需审批或 admin 限定 + 审计日志；新增工具/路由时按判定标准逐项核对补充。
