## Scope and behavior

- [Database runbook](../../enterprise-agent/deploy/DATABASE_BOOTSTRAP.md) defines
  offline preview, isolated empty initialization, explicit legacy-copy adoption,
  administrator bootstrap, development demo opt-in, recovery and live acceptance.
- [Manifest](../../enterprise-agent/deploy/schema_manifest.json) pins managed
  version 1 and artifact SHA-256 hashes. The runner never auto-discovers historical
  `001`–`005` migrations or executes their shared-password backfills.
- [Schema baseline](../../enterprise-agent/deploy/init.sql) contains schema only.
  All eight existing fixture INSERT batches are preserved in
  [demo_seed.sql](../../enterprise-agent/deploy/demo_seed.sql), with the embedded
  password hash replaced by an operator-supplied transaction-local value. No
  business data is removed; no old SQL files or volumes are deleted.
- [CLI](../../enterprise-agent/app/core/db_bootstrap.py) provides offline `plan`,
  read-only `status`, and explicit `apply/admin/demo --execute` operations. It
  uses existing psycopg/bcrypt dependencies, transaction advisory locks and
  connection/statement/lock timeouts. Pending migrations and their ledger commit
  together. Missing credentials, incompatible legacy shape or history drift stop
  the operation; unknown/partial legacy databases are not silently adopted.
- Admin bootstrap refuses an existing administrator and never resets credentials.
  Demo requires development, mock business providers, an empty dataset and a
  password; a seed checksum marker prevents repeated insertion. No default
  accounts or demo data are generated by PostgreSQL/API/worker startup.
- [Schema gate](../../enterprise-agent/app/core/schema_contract.py) checks current
  history, required columns/types/widths, password NOT NULL and valid index
  names/uniqueness flags. Database initialization publishes no session factory on
  failure; API/worker stop before audit or business queue work. Health rechecks
  the contract using safe error codes.
- Both Compose files stop mounting SQL into PostgreSQL's automatic entry point.
  The production image packages the manifest and seed; production Compose enforces
  password authentication for API/worker. This limited guard does not close C05.
  No dependencies installed, services started, paid API calls made or database
  connections opened in this increment.
- Updated DEPLOY/quickstarts/operations guide, ROADMAP/ISSUES/baseline, indexes, AGENTS and OpenSpec.
  Only task 1.4.1 is checked; 1.4 and 1.4.2 remain open. No main-spec synchronization
  or archive is claimed while runtime acceptance is missing.
