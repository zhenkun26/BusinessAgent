### Implementation and review

- `SessionFence` uses a PostgreSQL database-clock lease and unique owner token. A row lock
  serializes takeover, session start and publication; expired ownership cannot renew.
  Redis remains the shared admission/cancellation signal. A lost PG lease cancels work
  even when Redis renews. Both guards fail closed without business retry.
- Every persistent run has a separate physical saver thread. Late raw checkpoint/pending
  writes can leave orphan data, but cannot overwrite a successor's thread. A PostgreSQL
  transaction publishes the exact accepted ID and terminal status/token totals together.
  Stale failure/cancel/start/release callbacks cannot update the successor. Tokens are
  counted once for accepted turns, not as an accounting claim about failed model costs.
- Normal responses and SSE final success require confirmed publication. Commit uncertainty
  returns failure without claiming rollback; a successfully committed pointer may remain.
  History reads accepted IDs with bounded reads and read-only legacy compatibility. Missing
  referenced snapshots/backend mismatch fail closed. Swallowed cancellation cannot become
  successful publication. Direct persisted graph calls require owned run context.
- Additive schema v8 is declared/checksummed; v1–v7 SQL bytes are unchanged. Older API
  writers must be drained/stopped before migration; mixed binaries are unsupported.
  No migration or checkpoint setup ran. Pending/running rows and orphan raw writes are
  retained; no filesystem/store deletion, automatic recovery or replay was introduced.
- C04/C08/C09 fixtures now express the ownership boundary. Token tests verify atomic
  publication instead of the removed asynchronous writeback helper. C21's migration
  assertion retains the v7 check and adds the new latest v8 expectation. No skipped-test
  workaround, threshold reduction or unrelated implementation change.
