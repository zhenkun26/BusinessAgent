## PR-BA-001：MinIO 备份缺口导致向量数据不可恢复

- **真实现象与影响**：第一轮隔离 DR 演练恢复 PostgreSQL 和 etcd 后，Milvus 元数据行数存在，但 segment 缺失、load 挂起，知识问答数据层不可恢复。
- **复现条件**：只备份 pg_dump 与 etcd snapshot，不备份 MinIO/Milvus 对象卷；按 `ISSUES.md` I-12 的隔离 Compose 演练步骤恢复。
- **调查过程**：分别核对 PG 行数、etcd 键数量、Milvus collection row_count 和 load 状态，定位“元数据恢复”与“对象数据恢复”之间的缺口。
- **失败方案**：只恢复 PG 和 etcd；该方案无法恢复 Milvus segment。
- **最终根因**：备份清单遗漏承载向量数据本体的 MinIO 对象存储。
- **最终修复**：`backup.sh` 增加 MinIO 与 milvus 本地卷 tar 备份；部署手册同步完整恢复步骤。
- **验证结果**：第二轮演练恢复 collection、row_count=28，真实 query 返回数据，RTO 约 194 秒。
- **防止复发**：备份四件套清单、隔离 DR 演练和恢复后真实 query 验收。
- **个人反思**：恢复元数据不等于恢复系统；每个索引/元数据服务都必须映射到真实数据本体。

## PR-BA-002：跨机器迁移后本地启动环境缺失

- **真实现象与影响**：Windows → macOS 后出现 Failed to fetch、页面打不开。
- **复现条件**：后端未启动、Docker daemon 未启动、项目 Python 环境和数据库未初始化；旧启动方式绑定 127.0.0.1，且复制 URL 时带入 `**`。
- **调查过程**：检查 8000 端口、Docker、Python 环境、数据库迁移、IPv4/IPv6 访问和实际请求日志。
- **失败方案**：直接打开前端文件或沿用旧启动命令；无法提供完整 API 依赖。
- **最终根因**：启动依赖未被迁移和自检脚本显式表达，且 URL 文案污染进入请求。
- **最终修复**：补齐本机环境、初始化流程、`APP_HOST=0.0.0.0`、URL 尾部 `**` 清洗和 macOS 启动脚本。
- **验证结果**：`/health`、登录、`/ui` 和 `/ui**` 均按 I-09 记录验证通过。
- **防止复发**：启动脚本增加 Docker/6379 检查；README 明确环境前置条件。
- **个人反思**：跨机器问题首先是可启动性和诊断性问题，不应只从业务代码排查。

## PR-BA-003：原生 Redis 与 Docker Redis 端口冲突

- **真实现象与影响**：限流器降级内存，checkpointer 降级 PG，聊天失败。
- **复现条件**：Homebrew Redis 无密码占用 127.0.0.1:6379，应用配置却按 Docker Redis 密码认证。
- **调查过程**：对照端口占用、Redis AUTH 错误、应用降级日志和 `/ready` 后端状态。
- **失败方案**：只重试应用连接；端口仍由错误实例占用，认证持续失败。
- **最终根因**：同端口存在两个语义不同的 Redis 实例。
- **最终修复**：停止原生 Redis；启动脚本加入 6379 冲突自检。
- **验证结果**：限流器恢复 Redis 生产模式，Redis checkpointer 初始化成功，聊天返回正常。
- **防止复发**：启动前端口检查和 `/ready` 后端标识。
- **个人反思**：降级链必须暴露当前后端，否则“可用”会掩盖配置错误。

## PR-BA-004：对抗性审查中的认证、隔离与配置问题

- **真实现象与影响**：I-11 记录了 JWT 默认密钥、认证绕过、默认数据库口令、Redis 密码日志泄漏、禁用用户越权、CORS、PG checkpointer 500、Milvus 表达式注入、审计缓存丢失和 TraceId 缺失等问题。
- **复现条件**：按生产审查清单逐项运行代码和配置检查；具体复现步骤以现有《生产对抗性审查与部署验收报告》为准。
- **调查过程**：逐文件审查 API、认证、数据库、Redis、Milvus、审计和配置路径，并补测试。
- **失败方案**：仅依赖默认配置和单一路径测试，无法覆盖降级、越权和错误配置组合。
- **最终根因**：安全边界和降级行为没有在所有入口统一约束，部分配置仍存在危险默认值。
- **最终修复**：按 I-11 记录逐项修复，并补 18 项测试。
- **验证结果**：I-11 记录 36/36 测试、1000 并发、生产镜像冒烟和 K8s 清单校验通过；具体报告仍是本条唯一事实源。
- **防止复发**：CI 安全扫描、`/ready` 可观测、RBAC/隔离回归、配置校验和审计检查。
- **个人反思**：对抗性审查必须将“危险默认值”和“降级掩盖错误”作为同一类系统性问题处理。
