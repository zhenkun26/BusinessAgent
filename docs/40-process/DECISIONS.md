# DECISIONS · 设计决策记录

> 决策记录的单一事实源。格式：背景 → 决策 → 放弃了什么 → 改判条件。
> 内容从产品文档第十章与 Agent 项目面试备稿提炼，新增决策追加不改写。

## 1. LangGraph 显式状态机，而非 ReAct 自由循环 / AutoGen

- **背景**：企业场景要求路由可预测、权限决策点可审计、状态可恢复。
- **决策**：StateGraph 显式建模 planner → fan-out → aggregator，路由是代码而非 LLM 即兴决策。
- **放弃**：ReAct 应对完全未知任务的开放性、AutoGen 的多 Agent 自由对话。
- **改判条件**：开放任务占比显著上升时，在 executor 内嵌受限 ReAct 子循环，不推翻主图。

## 2. Supervisor 集中决策（单一 planner），而非去中心化路由

- **背景**：RBAC 与审计的落点需要集中。
- **决策**：planner 统一做意图分类 + 任务分解，executor 只执行。
- **代价**：planner 是决策单点；用超短消息短路 + 本地闲聊预判 + 云端运行时回退 + 规则降级四层缓解。
- **改判条件**：出现「意图分类覆盖不了」的开放式任务域。

## 3. 拆三个子 Agent（Knowledge/Analysis/Execution），而非单 Agent + 工具

- **背景**：三类任务的上下文构造、权限模型、失败语义差异极大。
- **决策**：独立 Agent + 统一 AgentResult 契约，可独立评测、独立换模型。
- **代价**：多结果需一次 primary LLM 汇总；用「单结果直通不调 LLM」压回成本。

## 4. Mock-first 工具策略，契约完全对齐真实 API

- **背景**：真实业务系统缺位，但安全链路（RBAC/Saga/审批）必须提前验证。
- **决策**：工具 Mock 实现 + pydantic schema/补偿语义对齐真实契约，`_call_external` 预留切换点。
- **放弃**：Mock 测不出真实系统的脏数据与延迟分布。
- **改判条件**：真实系统 API 契约冻结即切换（见 complete-business-processes 外部系统接入）。

## 5. 全栈降级链 + 降级必须可观测

- **背景**：任一依赖故障不宕机；但降级会掩盖配置错误（真实踩坑：memory 后端掩盖向量检索未生效）。
- **决策**：LLM/检索/Checkpointer 三条降级链；`/ready` 与响应暴露当前生效后端。
- **原则**：降级兜底可用性，不兜底可观测性——每条降级链必须配「我在降级」的信号。

## 6. Saga 补偿失败不阻断流程

- **背景**：分布式场景没有真正的回滚（邮件发出只能发撤回信）。
- **决策**：补偿失败记录 `compensation_errors` 继续返回，运维介入。
- **原则**：最终一致性 + 可观测 > 虚假的强一致。

## 7. 审批后按发起人角色终审（批准不越权）

- **背景**：审批系统不能成为提权通道。
- **决策**：经理批准后，工具仍按发起人角色过 RBAC（执行前显式预检 + 工具层终审），审计分离记录 decided_by 与 executed_as_*。
- **放弃**：审批人代办下属操作的便利性。

## 8. 本地小模型承担高频简单任务，云端只留给推理

- **背景**：云端成本与数据不出内网诉求。
- **决策**：闲聊判断/自评/意图分类/计划解析走本地 qwen3.5:4b；任务分解/分析报告/多结果汇总走 deepseek-v4-pro。
- **例外**：execution 工具选择云端 flash 优先（本地 4B 会选错工具，实测）。
- **原则**：按任务的最小能力需求配模型。

## 9. 拒答优于编造；数字永远来自 Python 聚合

- **背景**：企业知识库给错误制度答案的代价远高于「不知道」。
- **决策**：低置信度明确拒答；分析数字由 Python 真实聚合，LLM 只负责表达。

## 10. agent_results 用可重置 reducer

- **背景**：标准 `operator.add` 在断点恢复后会把上一轮结果追加进新一轮。
- **决策**：`_resettable_add`——右值为空列表即重置，非空即累加，一个 reducer 兼顾两种语义。

## 11. 文档六大层分类 + 单一事实源（2026-08-04 新增）

- **背景**：根目录 36 个 md 散落，进度/决策/坑记录多处重叠，无版本历史。
- **决策**：`docs/` 六大层（产品方案/产品文档/操作手册/过程记录/工程文档/知识数据库）+ 归档层；ROADMAP/ISSUES/DECISIONS 各为单一事实源；`interview/` 独立承载面试与演示资产；Git 全程版本控制。
- **放弃**：保持根目录散文档的「所见即所得」。
- **改判条件**：文档规模大到单层 README 索引不足时，引入文档站点生成器。
